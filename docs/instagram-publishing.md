# Instagram sign-in, publishing and comparisons

Settings → Instagram now has browser sign-in when the optional HTTPS authorization service is configured, plus the existing developer-token connection. The server keeps the Meta app secret; the desktop stores the resulting user token with OS encryption. See [authorization deployment](../services/instagram-auth/README.md). The code is present, but browser login remains unconfigured until a server/domain, Meta app settings and credentials are supplied and tested.

Open **Publishing queue** in Instagram settings to create a Reel draft. Supply the connected account, a durable public HTTPS video URL, caption, feed preference and optional local publishing time. Saving a draft sends nothing to Instagram. **Review and approve** displays those exact fields before approval. Agent analytics tools remain read-only and cannot approve or publish.

Approved items run while UVE is open and online. They may publish late after reopening; anything more than 24 hours overdue stops for review. A changed connection pauses all outstanding approvals, including future schedules. Cancellation prevents subsequent queue steps until a publish request has already started; an already sent request cannot reliably be recalled. Removing an item removes only its local queue record and never deletes an Instagram post.

The queue saves each step before making an outbound request. It creates a Reel container, checks processing status, and publishes only once the container reports `FINISHED`. Pending known containers can resume across restarts. A lost publish response or crash during publication becomes **needs review**, with no automatic retry. **Check Instagram status** can confirm a published container without resending the publish operation. An inconclusive status remains for manual review; check Instagram before creating another draft. Missing permissions and processing failures are reported, not silently retried.

Instagram Login publishing requires `instagram_business_content_publish` and a Creator or Business account with the necessary Meta app access. Instagram fetches the supplied public video URL. UVE does not yet provide hosted media storage or automatically upload local exports; local paths, IP addresses, local hostnames, embedded username/passwords and `access_token` URL parameters are rejected. Use an MP4/MOV that satisfies Instagram's current Reel requirements and keep its URL available until publishing completes. Meta performs final format/permission validation. This implementation does not assume Facebook Login's resumable-upload flow works with Instagram Login.

The queue is bounded to 200 records and lives in the app's `instagram/publishing.json`, with locked serialization and atomic fsynced writes. A damaged or unsavable queue stops publishing. All implementation tests use fake responses and temporary folders; no personal account was queried or published to during development. Live authorization and publishing still require deliberate acceptance with an authorized account and public media hosting.

Analytics adds **Compare two posts**, using the real cached posts already synced. It shows latest lifetime values, their difference, and measurement age. Missing data remains missing; zero baselines do not generate invented percentage gains. Unequal post ages, audiences and timing are visible caveats. These are observations to guide editing, not a causal experiment or predicted improvement.
