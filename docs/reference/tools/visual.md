# Local visual footage search

In **Footage → Visual B-roll**, index imported local videos, search sampled frames and preview timestamped candidates. Copy a candidate's verified source range to ask the agent to audition or insert it. Search and indexing never change the timeline or original media.

**Labels and visible text** uses Apple Vision image classification, OCR and people counts. It requires no model download. All meaningful keywords must match evidence from the same sampled frame; a small synonym list supports `bike`/`bicycle`, `runner`/`running`, and `ocean`/`sea`. A sign saying “bicycle” can match even without a visible bicycle. Detector confidence is not proof.

**Description similarity** compares a natural-language description with image embeddings using local CLIP. Select this search method, explicitly click **Download description model (156 MB)**, then **Index descriptions** and **Find similar frames**. For example, a description such as “a person being interviewed on a television news program” can retrieve a studio frame even when those words do not appear in its labels. The signed cosine score is a ranking measure, not a probability. CLIP can miss relationships, negations and actions; it does not recognize identities or understand events across time. English works best; input is truncated to CLIP's 77-token limit. It always ranks available candidates, so an irrelevant query can still return results. Preview each candidate.

The optional model is [OpenAI CLIP ViT-B/32](https://github.com/openai/CLIP), under the MIT license, using the [Xenova ONNX conversion pinned to revision d15189d7028b43f1d3e65039190477f6af591c2a](https://huggingface.co/Xenova/clip-vit-base-patch32/tree/d15189d7028b43f1d3e65039190477f6af591c2a). UVE downloads only six fixed model/config/tokenizer files (155,851,446 bytes total) from Hugging Face and its download CDN. Every file is verified against its pinned SHA-256 before use, including previously cached files. The matching ONNX WASM runtime is bundled in the app. No footage, images or query text are uploaded; inference runs in a dedicated local worker. Download cancellation terminates the worker and retains only completed verified files for retry. Inference works offline once the files are cached. MCP editing tools cannot trigger the model download; the app provides an explicit download action.

Both modes use the same sampling grid: five seconds by default, growing as needed to cap analysis at 720 frames for videos up to two hours. Orientation is applied. Native indexing records the actual decoded presentation timestamp; source times subtract the editor's video-track origin, including MP4 files with an initial track offset. Description embeddings decode those same observed frames. Brief shots may fall between samples. Both modes return the observed source timestamp plus a suggested audition range around it. Ranges are not detected shot boundaries and do not establish continuous visibility. Insertion remains an explicit edit through the agent or editor. Older visual indexes using nominal sampling times are rebuilt locally by clicking **Index visuals**, then **Index descriptions**; model downloads are retained.

`visual_index` builds visual evidence; set `descriptions: true` to also build CLIP embeddings after the user has downloaded the model. `visual_search` uses `mode: "keywords"` by default, or `mode: "description"` for cosine similarity. The latter requires a nonempty description and reports `method: "local-clip-cosine"` plus `descriptionUnindexed` paths. `visual_status` reports current native indexing status. Search refreshes source fingerprints before relying on results. Preview and copy revalidate the source again. Changed or unavailable sources are reported separately; a missing match is not proof of absence. Native indexing saves completed sections of at most two minutes for resume after cancellation or restart. Canceling optional description indexing retains completed videos and discards partial video embeddings.

The project stores `.cutroom/visual-index.json`, keyed by full source SHA-256 and engine version. Unchanged renamed or copied media reuse evidence across restarts. Changed source bytes invalidate it. Saves use a project lock, temporary file, fsync and atomic rename. Metadata is bounded to 500 source entries and 64 MB; a full or damaged cache is reported without replacing it. The rebuildable index is excluded by Collect Project.

CLIP vectors live in this Mac's app storage (IndexedDB), bound to the full source SHA-256, exact sampled times and model revision. Every vector must contain 512 finite, normalized values. The cache retains at most 20,000 frames, evicting least recently used complete source records; each indexing/search batch has the same bound. Model files use the local browser cache. These rebuildable caches are not copied with a collected project, and a source can require reindexing after cache eviction. Renaming or copying identical media can reuse embeddings.

Apple references: [image classification](https://developer.apple.com/documentation/vision/vnclassifyimagerequest), [text recognition](https://developer.apple.com/documentation/vision/vnrecognizetextrequest). Embedding implementation follows [Transformers.js CLIP projection models](https://huggingface.co/docs/transformers.js/v3.8.1/api/models). Native visual indexing requires macOS 13 or later.
